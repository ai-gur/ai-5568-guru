## הנכס שכבר קיים

לכל אחת מ-60 שורות הקטלוג יש כבר מבנה `remediation` מלא:

```
goalHe        משפט אחד: מהו מצב הסיום שהעמוד צריך להגיע אליו
instruction   הוראה קונקרטית לסוכן קוד. Markdown, עשוי להכיל קטעי קוד.
hebrewStrings מחרוזות עברית שהתיקון נדרש להן — כדי שהסוכן לא ימציא אותן
effort        low | medium | high — לצורך סדר הטיפול בלבד
```

פילוח מאמץ: 32 נמוך, 20 בינוני, 8 גבוה.

`hebrewStrings` הוא פרט חשוב: הוא מונע מסוכן להמציא ניסוח עברי לא תקני לרכיבי ממשק — למשל תבנית `'לוגו {{שם החברה}}'` לטקסט חלופי של לוגו.

---

## סדר הטיפול

תיקונים זולים וּודאיים קודם. סוכן שנגמר לו התקציב צריך להישאר עם ניצחונות בכיס, לא עם הפריט הקשה ביותר חצי-גמור.

**הפרדה חובה:** שורות שלא ניתנו לאימות מופרדות מממצאים אמיתיים. סוכן שמקבל "47 כשלים" כש-17 מהם מעולם לא נבדקו באמת — ימציא תיקונים לדברים שלא היו שבורים. זה גרוע יותר מלהשאיר אותם.

---

## כללי איסור — נאכפים, לא מומלצים

הדרכים הנפוצות שבהן סוכן "מתקן" נגישות והופך את הדוח לטוב יותר ואת האתר לא:

| ❌ אסור | למה |
|---|---|
| **להמציא טקסט חלופי** לתמונה שהסוכן לא יכול לראות | הדוח נראה תקין, המשתמש בקורא מסך מקבל שקר |
| **למחוק את הרכיב הפוגע** | הכשל נעלם מהדוח; הפונקציונליות נעלמת מהאתר |
| **להוסיף ווידג'ט overlay** | מסתיר כשלים במקום לתקן. מגונה בקהילת הנגישות, נתבע בבתי משפט |
| **לסמן קריטריון כמתוקן בלי להריץ מחדש את בדיקתו** | הופך את ה-delta לבדיה |
| **לדחוף ל-`main`** | תיקון נגישות שובר דברים. תמיד Pull Request |

זה חל על ה-fixer, על פלאגין ה-WordPress, ועל כל סוכן שצורך את הסקיל.

---

## ה-fixer — סוכן קוד → Pull Request 💰

```
תוצאת סריקה
     │
     ▼  חיבור מאגר Git
  סוכן קורא remediation.instruction
     │
     ▼  ענף חדש
  מבצע תיקונים לפי סדר מאמץ
     │
     ▼  הרצה חוזרת של הבדיקה הספציפית לכל תיקון
  Pull Request + דוח delta
     │
     ▼
  בן אדם סוקר ומאשר
```

**נקודת המפתח:** הסוכן מריץ מחדש את הבדיקה של הקריטריון שתיקן, לפני שהוא מסמן אותו כמתוקן. בלי זה הוא מדווח על עבודה שלא בוצעה.

---

## לולאת ה-delta

מפתח הזהות היציב הוא `(targetUrl, itemId, locator)` — כבר קיים בסכימה.

דוח ההשוואה מציג **ארבע** קטגוריות, לא שלוש:

| | קטגוריה | הערה |
|---|---|---|
| ✅ | **תוקן** | אומת בהרצה חוזרת |
| ⚠️ | **עדיין שבור** | |
| 🔴 | **נשבר חדש** | תיקון נגישות אחד שובר אחר בקלות מפתיעה. **חובה להציג בבירור.** |
| ❔ | **עדיין לא ניתן לאימות** | **לעולם לא נספר כהתקדמות.** |

שתי הקטגוריות האחרונות הן מה שמפריד בין כלי ישר לכלי שמוכר אשליה. בלעדיהן המוצר בתשלום ייראה טוב יותר ממה שהוא — וזה בדיוק מה שאנחנו לא מוכרים.

**חוק הגרסה:** השוואה חוקית רק בין דוחות של **אותה `catalogueVersion`**. אחרת מוצג מעבר גרסה מפורש, כי "הקריטריון נכשל עכשיו ולא נכשל קודם" יכול לנבוע משינוי באתר או משינוי בתקן — ואלה שני דברים שונים לגמרי מבחינת הלקוח.

### חינם — בזמן כתיבה

סרגל צד בעורך הבלוקים שבודק תוך כדי כתיבה. מודע לעברית ו-RTL.

בודק: טקסט חלופי חסר, דילוג בהיררכיית כותרות, טקסט קישור גנרי, ניגודיות, כותרות טבלה.

מחולל את פריטי תקנה 35: עמוד הצהרת נגישות, פרטי רכז נגישות, ווידג'ט העדפות.

### בתשלום — תיקון בכמות

משיכת תוצאות סריקה ותיקון מרוכז.

**מעקות חובה:**

```
תצוגה מקדימה של diff → אישור מפורש → שמירת revision → אפשרות rollback
```

**היקף:** תוכן פוסטים, טקסט חלופי של מדיה, תפריטים והגדרות.

**⚠️ לא נוגע בקובצי תבנית כברירת מחדל.** שם שוברים אתרים. שינוי קובצי תבנית דורש בחירה מפורשת של המשתמש והבנה שהוא לוקח סיכון.
