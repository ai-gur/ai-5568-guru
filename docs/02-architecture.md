# 02 — ארכיטקטורה

## הבעיה שהמבנה הזה פותר

בפרויקט הישן `packages/criteria` **קבור בתוך** `services/scanner`. הראיה: כל קובץ במנוע מייבא `'../../../criteria/src/schema.ts'`.

המשמעות: הקטלוג הוא איבר פנימי של הסורק ולא חבילה משותפת, ולכן שלושת המוצרים לא יכולים לצרוך אותו. זה בדיוק הכשל שיגרום לסקיל לבנות מול תקן אחד, לפלאגין מול שני, ולסורק להכשיל אותם מול שלישי.

          (נציבות · מת"י · W3C)          v2026.08.1

              ┌───────────────┬───────────────┼───────────────┐

              ▼               ▼               ▼               ▼

הדפוס **כבר קיים ועובד** בפרויקט הישן: `emit-skill-references.ts` מייצר את קובצי הייחוס של הסקיל מ-`criteria.json` בדיוק מהסיבה הזו — כדבריו, "אם הם יסטו, סוכן בונה מול תקן אחד ונבדק מול אחר". הארכיטקטורה החדשה מרימה את הדפוס מפרט למרכז, ומוסיפה לו גרסאות.

**כלל הברזל:** אף צרכן לא כותב קריטריון משלו. מי שצריך את הקטלוג בשפה אחרת — מייצר אותו, לא משכפל אותו.

**הערה על שיטוח:** בפרויקט הישן ל-`services/scanner` יש `packages/` משלו — workspaces בתוך workspaces. המבנה הזה משוטח לתוך המונורפו הראשי.

## שלושת החוזים

חוזה הוא ממשק שאסור לשבור בלי מיספור גרסה. שלושה כאלה:

### 1. `packages/criteria` — הקטלוג

```
catalogueVersion : "2026.08.1"
effectiveFrom    : "2026-08-01"
sources[]        : { url, retrievedAt, sha256 }
items[]          : { id, form: {...}, engine: {...} }
```

שתי שכבות שנשמרות מופרדות בקפידה:

- **`form`** — טקסט מועתק מילולית מטופס הנציבות. ייבוא מחדש דורס אותו. **אין לערוך ביד.**
- **`engine`** — איך *אנחנו* מכריעים: מיפוי כללי axe, בדיקת תחולה, פרוסת ראיות, רובריקה, הוראת תיקון. יושב ב-`overrides.ts` לפי מזהה שורה, ולכן ייבוא מחדש **לא הורס אותו**.

### 2. `packages/report-contract` — תוצאות הסריקה

הממשק בין הסורק החינמי ל-fixer בתשלום, ובין הסורק לפלאגין. **שבירה שלו שוברת את המודל העסקי.**

מכיל `ScanReport`, `TargetReport`, `CheckResult`, `Finding` — וחובה גם את `catalogueVersion` שהפיקה את הדוח.

מפתח הזהות של ממצא: `(targetUrl, itemId, locator)`. זה מה שמאפשר את לולאת ה-delta.

### 3. ערוץ העדכון — HTTP

איך פלאגין WordPress מותקן אצל לקוח מקבל קטלוג חדש. **חוזה HTTP, לא ספרייה** — כי הפלאגין רץ על שרת של מישהו אחר ולא נשלט על ידינו.

## תשתית

`aiguru.co.il` כבר יושב על Cloudflare, ולכן הקצה שם. הנתונים והאימות ב-Supabase.

### Cloudflare — קצה

- **Pages / Workers** — אפליקציית `readiness.aiguru.co.il` ושער ה-API
- **R2** — דוחות (HTML/XLSX/PDF/JSON) וצילומי מסך. **קישורים חתומים בלבד.**
- **Queues** — תזמון עבודות סריקה ואירועי סיום
- **Secrets** — מפתחות ספק AI, אישורי Supabase, טוקן הסורק. אף פעם לא לדפדפן.

### Supabase — נתונים ואימות

Postgres + Auth + RLS. נבחר על פני D1 כי ל-Cloudflare אין שירות אימות משתמשים מקביל, והסכימה הקיימת עם RLS כבר כתובה.

טבלאות (אחרי שינוי השמות): `workspaces`, `workspace_members`, `projects`, `review_runs`, `report_artifacts`, `domain_verifications`, `subscriptions`.

### קונטיינר פרטי — הסורק

הסורק דורש Playwright (דפדפן headless), Node 22+ וסיידקאר Python לניתוח מסמכים. **הוא לא יכול לרוץ על Cloudflare Workers.**

רץ כשירות נפרד, פרטי, מאומת ומוגבל בקצב בנפרד. הקצה מדבר אליו דרך API פנימי בלבד.

> היכן בדיוק רץ הקונטיינר — טרם הוכרע. ראו [05-open-questions.md](05-open-questions.md).

## מנוע הסריקה — ארבע שכבות ראיות

נשמר מהפרויקט הישן. הערך שלו הוא בדיוק בהפרדה הזו.

| שכבה | מה | מכריע |
|---|---|---|
| **axe-core** | כללים דטרמיניסטיים סטנדרטיים | 5 שורות במלואן, תורם ל-40 |
| **כללים מותאמים** | מה ש-axe לא מכסה: חובות ישראליות, RTL, כותרות מדומות, placeholder כתווית | תורם לרוב השורות |
| **פרובים חיים** | Playwright: הליכת מקלדת (Tab בלבד, לעולם לא Enter/Space כדי לא לשנות את העמוד), צילומי מסך, ניגודיות מחושבת, זום | 5 קריטריונים התנהגותיים |
| **שיקול דעת (LLM)** | פרוסת ראיות צרה + רובריקה בעברית. עובדות מפורשות, לא HTML גולמי | 55 שורות |

**מסמכים:** הורדה → סיידקאר Python (pdfplumber, pymupdf, pikepdf, python-docx/pptx, openpyxl) → **עובדות בלבד, לעולם לא הכרעות**. ההכרעה חוזרת לשכבת Node כדי שעמודים ומסמכים יעברו את אותם כללי קדימות.

**אימות מיפוי axe:** מזהה כלל שלא קיים בבילד המותקן גורם לשגיאה קשה בהפעלה — כדי ששדרוג של axe לא יהפוך שורה בשקט ל"לא ניתנת לכישלון".

## אבטחה

- **SSRF:** חסימת טווחים פרטיים, loopback, link-local ו-reserved **אחרי פתרון DNS**. בדיקת מחרוזת לבדה לא מספיקה — `internal.example.com` יכול להצביע ל-`10.0.0.5`.
- **הרשאת סריקה:** סריקה קלה (~5 עמודים) פתוחה; סריקה מלאה דורשת הוכחת בעלות (רשומת DNS TXT או קובץ בשורש).
- **כיבוד `robots.txt`** ו-rate limiting לכל דומיין יעד.
- **קישורים חתומים** לכל נכס ב-R2.
- **הריפו ציבורי** — אין סודות, כתובות פנימיות או נתוני לקוחות בשום קובץ.
- מפתחות API בצד שרת בלבד. אף פעם ב-`NEXT_PUBLIC_*`.
