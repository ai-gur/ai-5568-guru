# 09 — טופולוגיית הריפו

## התבנית: משטח × יכולת

כל מוצר ברשימה הוא **משטח**, ולכל משטח שני צדדים:

| משטח | קריאה — לזהות ולהסביר 🆓 | כתיבה — לתקן 💰 |
|---|---|---|
| ווב | הסורק | סוכן → Pull Request |
| WordPress | בדיקה בעורך | תיקון מרוכז in-place |
| סוכן LLM | סקיל האותרינג | **סקיל מתקן — 🆓 חינמי** |
| *(עתיד: Shopify, Wix, VS Code)* | | |

מגדירים את זה פעם אחת כממשק, והוספת משטח חדש היא **מילוי תבנית ולא המצאת מוצר**. בלי זה, כל משטח ימציא מחדש את סדר התיקון, את מעקות הבטיחות ואת האימות.

### למה בדיוק חמש

**`criteria`** — מה התקן דורש. עמוד השדרה.
**`report-contract`** — מה מצאנו. הגבול בין הסורק לכלים.
**`remediation`** — מה צריך להשתנות, לכל קריטריון. זה **ידע**, ולכן חינמי.
**`fix-plan`** — התוכנית: רשימה מסודרת ומודעת-התנגשויות של שינויים.
**`delta`** — האם זה עבד. השוואה בין שני דוחות.

### הקו העסקי עובר בדיוק כאן

> **החינם נותן לך את התוכנית. התשלום מריץ אותה.**

`fix-plan` הוא **חוזה ציבורי** — מפתח יכול לקבל את התוכנית המלאה, לקרוא אותה, ולבצע ידנית.
ה-**planner** שממיר דוח לתוכנית, וה-**appliers** שמריצים אותה, הם אוטומציה — ולכן פרטיים.

`delta` ציבורית מסיבה עניינית: היא הופכת את המסלול החינמי לשלם. תקן ביד → סרוק שוב → ראה בדיוק מה השתפר. בלי זה, המסלול החינמי מסתיים בדוח ולא בסגירת מעגל.

## הגבול: npm, לא submodule

הריפו הפרטי עושה `npm i @ai5568/criteria@^2026.8`.

**למה לא monorepo אחד עם תיקייה פרטית:** אין ריפו ציבורי אמיתי, או שנדרש mirroring — וזה וקטור דליפות.
**למה לא submodule:** הפרטי היה יכול להושיט יד פנימה לכל קובץ. גרסה היא מה שמכריח את המשמעת.

**בונוס שאינו משני:** `npm i @ai5568/criteria` הופך את קטלוג ת"י 5568 לנכס שכל מפתח בישראל יכול לצרוך. זה משרת את המטרה הציבורית, וזה גם השיווק הכי טוב שיש.

## ממשק המשטח

כל applier מממש את אותו ממשק. שתי דרישות אינן ניתנות למשא ומתן:

```ts
interface Surface {
  readonly id: string;                       // 'git' | 'wordpress' | …
  /** האם המשטח הזה יכול לפעול על הצעד הזה בכלל? */
  supports(step: FixStep): boolean;
  /** ביצוע. מחזיר תיאור שינוי שניתן לבטל. */
  apply(step: FixStep): Promise<AppliedChange>;
  /** ⚠️ חובה. כל applier חייב לדעת לבטל את עצמו. */
  revert(change: AppliedChange): Promise<void>;
}
```

**`revert` בממשק ולא בהמלצה.** דרשנו preview ו-rollback לוורדפרס; להכניס את זה לחוזה אומר שכל משטח עתידי **יורש את המשמעת במקום להמציא אותה**.

**`supports` מחזיר false בגלוי.** applier שלא יכול לטפל בצעד אומר זאת, ומה שלא טופל מוצג ללקוח. מה שלא נעשה לעולם לא נספר כנעשה.

## פלאגין WordPress — למה החצי החינמי חייב להיות ציבורי

זו **לא רק פילוסופיה**: wordpress.org מחייב קוד פתוח ו-GPL כדי לארח פלאגין.

- `plugins/ai-guru-5568` — ציבורי, GPL, **מלא ושימושי כשלעצמו**
- `ai-guru-5568-pro` — add-on נפרד מהריפו הפרטי, דורש את החינמי. התבנית של Yoast

זה גם מונע את הפיתוי לשלוח פלאגין "ציבורי" עם קוד נעול בפנים — דבר שגם נפסל ב-wordpress.org וגם היה סותר את מה שאנחנו אומרים.

## הסקיל המתקן — חינמי, ובכוונה

**אי אפשר למנוע מסוכן LLM לתקן נגישות כשהדוח וההנחיות חינמיים.** מישהו עם Claude Code והדוח שלנו יגיע לאותה תוצאה. זו לא דליפה — זו המטרה עובדת.

לכן `skills/fixer` ציבורי וחינמי:
- לא עולה לנו טוקנים — הם של המשתמש
- מאיץ אימוץ של הסריקה החינמית
- משרת את המטרה יותר מכל רכיב אחר

**מה שבאמת נמכר, כי הוא דורש את התשתית שלנו:**

| | למה זה לא נשחק מהסקיל החינמי |
|---|---|
| **שהכלי יעשה זאת במקומך** | הסוכן שלנו, הטוקנים שלנו, PR מוכן. מי שלא רוצה להריץ סוכן משלם |
| **דלתא מאומתת** | הרצה חוזרת על התשתית שלנו — הוכחה, לא הצהרה |
| **WordPress in-place** | למי שאין לו לא ריפו ולא סוכן. זה הרוב, וזה הכסף |
| **ניטור ועדכוני תקן** | דורש שנעקוב אחרי התקן ברציפות |
